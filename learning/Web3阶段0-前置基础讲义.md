## 开篇：先建立直觉

区块链解决的核心问题是：**在没有可信第三方的情况下，让互不信任的各方对同一本账本达成一致**。

想象你记账：传统方式是一家银行/一个服务器说了算；区块链是**一大群人各自都持有一本账本，任何人改账，其他人都会发现并拒绝**。所以叫"分布式账本 + 去中心化"。

- **去中心化**：没有单一权威，由众多节点共同维护
- **不可篡改**：改一个地方会破坏整条链的哈希链条，别人立刻看出不一致（详见"哈希"）
- **账本公开**：交易记录全网可见（公开链）

> 记住这个直觉，后面所有概念（区块、共识、Gas、签名）都是围绕它展开的。

## 一、区块链核心概念

### 1.1 什么是区块与交易
- **交易（Transaction）**：一笔对账本的改动，比如 A 转给 B 1 ETH
- **区块（Block）**：一批交易打包在一起，加上时间戳、哈希、上一个区块的哈希等
- **链（Chain）**：每个区块都引用前一个区块的哈希，环环相扣成一条链 → 想改旧区块，就得重算它之后所有区块，工作量巨大

直觉：区块像账本的一页，页页相连，页码被哈希锁死，撕不掉。

### 1.2 节点（Node）
- 节点 = 运行客户端、参与维护账本的机器
- **全节点**：保存完整账本并校验每笔交易（最可信、最重）
- **轻节点**：只保存区块头，需要时向全节点要数据
- 谁在跑节点？矿工/验证者、交易所、钱包服务、开发者等

### 1.3 共识（Consensus）
共识 = 让众多互不信任的节点**对同一条链达成一致**的机制。
- **PoW（工作量证明）**：比特币。靠"挖矿"（算哈希难题）竞争记账权，谁先解出谁打包，全网络认可最长链
- **PoS（权益证明）**：以太坊现在的方式。验证者质押 ETH，被随机选中来提议/验证区块，作恶会被罚没质押

为什么需要：没有共识，节点会各记各的账，账本就分裂了。共识保证"大家认可的是同一条链"。

### 1.4 主网 / 测试网 / 本地链
| 类型 | 特点 | 用途 |
|---|---|---|
| **主网**（Mainnet） | 真实资产、真实手续费 | 生产环境 |
| **测试网**（Testnet，如 Sepolia） | 测试资产（免费领取），规则接近主网 | 无成本练习、开发调试 |
| **本地链**（anvil / hardhat） | 本地起一条链，秒出块、Gas 可设 0 | 本项目开发用（Foundry anvil，8545 端口） |

### 1.5 Layer 2（L2，二层）
- L2 是架在以太坊（L1）之上的扩容方案：把大量交易先放到 L2 快速处理，**定期把结果结算回 L1**
- 关键概念：**执行**（L2 上跑得快）与 **结算**（最终可信靠 L1 保障）
- 直觉：L1 是"最终法院/结算层"，L2 是"高速通道"，把账算完再报上去

## 二、密码学与账户

### 2.1 哈希函数（Hash）
哈希 = 把任意数据变成**固定长度的"指纹"**。
- 性质：**确定性**（同样输入→同样输出）、**单向**（很难由输出反推输入）、**雪崩**（输入变一点，输出完全变）、**抗碰撞**（几乎找不到两个输入产生同一输出）
- 以太坊用 **Keccak-256**；比特币用 **SHA-256**
- 为什么关键：区块之间的"哈希链条"、交易的指纹、地址的生成都靠它 → 这就是"不可篡改"的技术底座

直觉：指纹——稍微改动原文，指纹完全变样，伪造一个"同样指纹的不同原文"几乎不可能。

### 2.2 非对称加密（私钥 / 公钥）
- 一对密钥：**私钥**（你保密）与**公钥**（可公开）
- 私钥**签名** → 公钥**验证**：你用私钥签一份数据，别人用你的公钥就能验证"这确实是你签的"
- 以太坊账户体系：
  - **私钥**：256 位随机数，掌控它的=掌控资产（**丢了/泄露=资产丢失**）
  - **公钥**：由私钥推导
  - **地址**：由公钥哈希得到（通常 0x 开头 40 位十六进制），对外展示用的"账号"

直觉：私钥是"银行卡密码+签名笔"，公钥/地址是"账号"。别人给你地址能收款，但只有私钥才能花里面的钱。

### 2.3 钱包（Wallet）
注意区分：
- **链上资产**在链上，不在"钱包"里
- **钱包软件**（MetaMask 等）= 保管私钥 + 签名交易 + 展示余额的**工具**
- **助记词（Mnemonic）**：12/24 个英文单词，能恢复私钥（HD 钱包，BIP-39/44 标准）。**助记词=私钥**，必须离线妥善保管，见人=资产归人
- **托管（Custodial）**：平台帮你管私钥（如交易所账户）；**非托管**：私钥在你自己手里

### 2.4 UTXO vs 账户模型
- **比特币（UTXO 模型）**：余额 = 一堆"未花费的输出（Unspent Transaction Output）"。花的是"上一笔找零剩下的硬币"，像现金：找零、组合
- **以太坊（账户模型）**：每个账户直接记一个**余额 + Nonce（交易序号）**，像银行账户：转出直接减、转入直接加
- 为什么懂：理解充值/提现/找零逻辑时，两条链处理方式完全不同，是面试常见对比点

## 三、交易与 Gas

### 3.1 一笔以太坊交易有哪些字段
| 字段 | 含义 |
|---|---|
| `from` | 发起账户地址（由私钥签名） |
| `to` | 收款地址 / 合约地址 |
| `value` | 转账金额（wei） |
| `data` | 附加数据（给合约的调用指令，普通转账可为空） |
| `nonce` | 该账户的交易序号（防重放，从 0 递增） |
| `gasLimit` | 允许消耗的 Gas 上限 |
| `gasPrice` / `maxFeePerGas` | 单位 Gas 的价格 |
| `chainId` | 链标识（防跨链重放） |

### 3.2 Gas：为什么转账要手续费
- **Gas** = 执行交易消耗的计算资源计量单位；每条指令/每字节数据都要花 Gas
- **Gas 限额（gasLimit）**：本次交易最多允许消耗的 Gas（超了交易失败并退款未用部分）
- **Gas 价格（gasPrice）**：每单位 Gas 愿意付多少（wei）
- **手续费 ≈ gasUsed × gasPrice**；太低的 gasPrice 交易会一直 pending（没人打包）
- 本地链 anvil：gasPrice 可设为 0，练习无成本

直觉：Gas 是"矿工/验证者为你处理交易的辛苦费"，也是防止恶意刷链的限流阀。

### 3.3 EIP-1559（费用改革）
- 以太坊现行费用模型：**基础费（baseFee）+ 小费（priorityFee/小费给验证者）**
- 基础费随网络拥堵自动浮动，**部分会被销毁**；小费是给验证者加快打包的激励
- 钱包显示的是预估总费用；交易实际花费取决于执行时的拥堵

### 3.4 原生币 vs ERC-20 代币
- **原生币（原生 Ether）**：链本身的币，直接有 `value` 字段，转账不需要额外逻辑
- **ERC-20 代币**（如 USDT）：由**智能合约**发行的代币，转账是调用合约的 `transfer` 函数，`value` 通常是 0
- **decimals（精度）**：每个代币声明小数位，如 ETH 18 位、USDC 6 位。**金额要用最小单位（整数）算，不能假设都是 18 位** → 这是充值/对账出 bug 的高发点

### 3.5 交易哈希 / 回执 / 日志
- **交易哈希（txHash）**：这笔交易的指纹，全网可查
- **回执（Receipt）**：交易执行后的凭证，含 `status`（1=成功 / 0=失败）、`gasUsed`、`logs`、`blockNumber` 等
- **日志（Logs）**：事件记录（如 ERC-20 的 `Transfer` 事件），由合约 `emit` 产生；链上数据服务（如扫充值）主要靠解析日志
- 直觉：txHash 是"收据号"，回执是"交易详情单"，日志是"交易干了什么事"的可检索记录
