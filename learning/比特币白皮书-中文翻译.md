## 摘要

一个纯粹点对点（Peer-to-Peer）的电子现金系统，将允许在线支付直接从一方发送到另一方，而无需经过任何金融机构。数字签名提供了部分解决方案，但如果仍需要一个受信任的第三方来防止双重支付（Double-Spending），那么其主要好处就会丧失。我们提出一种使用点对点网络解决双重支付问题的方案。该网络通过对交易进行哈希运算、并将其纳入一条持续的、基于哈希的**工作量证明（Proof-of-Work）**链中，从而为交易打上时间戳；除非重做全部工作量证明，否则这条记录无法被更改。最长的链不仅作为所见证事件序列的证明，也证明了它来自最大的 CPU 算力池。只要控制算力的多数节点并非相互勾结攻击网络，它们就能生成最长的链，并超过攻击者。该网络本身只需极简结构。消息以尽力而为（best effort）的方式广播，节点可以随时离开并重新加入网络，并将最长的工作量证明链作为其离线期间所发生事件的证明。

## 1. 引言

互联网上的商业活动几乎完全依赖金融机构作为处理电子支付的**受信任第三方**。尽管这一系统对大多数交易来说运转良好，但它仍饱受信任模型固有缺陷的困扰。完全不可逆的交易实际上是不可能的，因为金融机构无法避免介入调解争端。调解的成本提高了交易费用，限制了实际可行的最小交易规模，切断了小额、随意交易的可能性；更广泛的代价是，对于不可逆的服务，我们失去了进行不可逆支付的能力。由于存在逆转的可能性，信任需求被扩散。商家必须提防顾客，向顾客索取比原本所需更多的信息。一定比例的欺诈被视为不可避免而被接受。这些成本和支付不确定性，可以通过当面使用实物货币来避免；但目前没有任何机制能在没有可信第三方的情况下，通过通信渠道进行支付。

我们所需要的是一个**基于密码学证明而非信任**的电子支付系统，使任何两个愿意交易的双方可以直接交易，而无需可信第三方。在计算上难以逆转的交易将保护卖家免受欺诈，而常规的托管（Escrow）机制也可以很容易地实现，以保护买家。本文中，我们提出利用点对点分布式时间戳服务器来生成交易时间顺序的计算证明，从而解决双重支付问题。只要诚实节点总体控制的算力多于任何相互勾结的攻击节点群体，该系统就是安全的。

## 2. 交易

我们将一枚电子币定义为一条**数字签名链**。每一任所有者通过数字签名来将币转移给下一任：对前一笔交易的哈希值和下一任所有者的公钥进行签名，并将这些数据附加到币的末尾。收款人可以验证签名，从而验证所有权的链条。

> **图1（原文）**：交易签名链示意图。每个 Transaction（交易）模块依次包含 Owner N's Public Key（所有者N的公钥）、Hash（哈希）、Owner N-1's Signature（所有者N-1的签名）；各模块之间通过 Verify（验证）箭头连接，模块下方的 Owner N+1's Private Key（所有者N+1的私钥）通过 Sign（签名）箭头生成对应的签名。

当然，问题在于收款人无法验证某位所有者是否曾对同一枚币进行过双重支付。一个常见的解决方案是引入一个受信任的中央权威（或称为"铸币厂" Mint），对每笔交易进行双重支付检查。每笔交易之后，币必须交还铸币厂以发行新币，只有直接从铸币厂发行的币才被信任为未被双重支付。这个方案的问题在于，整个货币体系的命运都取决于运行铸币厂的公司，每笔交易都必须经过它，就像银行一样。

我们需要一种方式，让收款人能够知道之前的历任所有者没有签署过更早的交易。就我们的目的而言，最早的那笔交易才算数，所以我们不关心之后双重支付的企图。确认一笔交易不存在，唯一的方法就是知晓所有交易。在铸币厂模型中，铸币厂知晓所有交易，并决定哪个先到。要在没有可信第三方的情况下实现这一点，交易必须被**公开广播**，并且我们需要一个让参与者就接收顺序达成单一一致历史的系统。收款人需要证明：在每笔交易发生时，多数节点都认可它是最先接收到的。

## 3. 时间戳服务器

我们提出的解决方案始于一个**时间戳服务器**（Timestamp Server）。时间戳服务器的工作方式是：对待加时间戳的数据块取其哈希，并广泛发布该哈希，例如发布在报纸或 Usenet 帖子上。时间戳证明了这些数据在此时刻必然已经存在（显然，否则无法进入哈希）。每个时间戳都在其哈希中包含前一个时间戳，从而形成一条链，每一个新增的时间戳都在强化其之前的时间戳。

> **图2（原文）**：时间戳链示意图。每个 Block（区块）包含多个 Item（条目）及省略号，区块输出经 Hash（哈希）运算后，作为下一个区块的前置关联标识，形成前后区块环环相扣的链式结构。

## 4. 工作量证明

为了在点对点的基础上实现分布式时间戳服务器，我们需要使用一种类似于 Adam Back 的 Hashcash 的工作量证明系统，而不是报纸或 Usenet 帖子。工作量证明涉及扫描查找一个值，当对其哈希（例如使用 SHA-256）时，哈希值以一定数量的零比特开头。平均所需工作量随所需零比特数量呈指数增长，而验证只需执行一次哈希即可。

对于我们的时间戳网络，我们通过不断递增区块中的**随机数（Nonce）**来实现工作量证明，直到找到一个使区块哈希满足所需零比特的值。一旦 CPU 付出努力使其满足工作量证明，除非重做这些工作，否则该区块就无法被更改。由于后续区块被链接在其后，更改该区块的工作量将包括重做它之后的所有区块。

> **图3（原文）**：工作量证明区块示意图。每个 Block（区块）包含 Prev Hash（前一区块哈希）、Nonce（随机数）、Tx（交易）区域；后一个区块的 Prev Hash 指向前一个区块，形成链式连接。

工作量证明还解决了多数决策中"代表权"的确定问题。如果多数是基于"一个 IP 地址一票"，那么任何能够分配大量 IP 的人都可以破坏它。工作量证明本质上是"**一个 CPU 一票**"。多数决策由最长的链来代表，因为这条链投入了最大的工作量证明努力。如果多数算力由诚实节点控制，诚实的链将增长最快，并超过任何与之竞争的链。要修改过去的区块，攻击者必须重做该区块及其之后所有区块的工作量证明，然后追上并超越诚实节点的工作。我们稍后将证明，随着后续区块的不断添加，较慢的攻击者追上的概率呈指数级下降。

为了补偿硬件速度的提升以及节点运行兴趣随时间的变化，工作量证明的难度由一个移动平均值决定，目标是维持每小时产出一定平均数量的区块。如果区块生成得太快，难度就会增加。

## 5. 网络

运行网络的步骤如下：

1. 新的交易被广播到所有节点。
2. 每个节点将新交易收集到一个区块中。
3. 每个节点为它的区块寻找一个困难的工作量证明。
4. 当一个节点找到工作量证明时，它将区块广播到所有节点。
5. 节点仅在所有交易都有效且未被花费过时才接受该区块。
6. 节点通过将已接受区块的哈希作为前一个哈希，着手创建链中的下一个区块，来表达对该区块的接受。

节点总是认为**最长的链是正确的**，并继续致力于扩展它。如果两个节点同时广播下一个区块的不同版本，有些节点可能先收到其中一个。在这种情况下，它们先处理首先收到的那个，但保留另一个分支，以防它变得更长。当下一个工作量证明被找到、其中一个分支变得更长时，平局即被打破；在另一个分支上工作的节点将切换到更长的那个分支。

新交易的广播并不一定需要到达所有节点。只要它们到达足够多的节点，很快就会进入一个区块。区块广播也能容忍消息丢失。如果一个节点没有收到某个区块，它会在收到下一个区块并意识到漏掉一个时请求它。

## 6. 激励

按照惯例，区块中的第一笔交易是一个特殊交易，它启动一枚由区块创建者拥有的新币。这为节点支持网络提供了激励，并提供了一种将币初始发行到流通中的方式，因为没有中央权威来发行它们。新币以恒定数量持续稳定地添加，类似于黄金矿工投入资源将黄金添加到流通中。在我们的情况下，投入的是 CPU 时间和电力。

激励也可以通过交易手续费来提供。如果一笔交易的输出值小于其输入值，差额就是交易费，并被添加到包含该交易的区块的激励值中。一旦预定数量的币进入流通，激励就可以完全转向交易费，并完全无通胀。

激励可能有助于鼓励节点保持诚实。如果一个贪婪的攻击者能够聚集比所有诚实节点更多的算力，他将不得不在两种选择间权衡：是用它来欺诈他人、偷回自己支付的款项，还是用它来生成新币。他应该会发现，遵守规则——这些规则使他获得比所有人加起来还多的新币——比破坏系统、损害自己财富的有效性更为有利可图。

## 7. 回收磁盘空间

一旦一枚币的最新交易被足够多的区块所"掩埋"，它之前已花费的交易就可以被丢弃以节省磁盘空间。为了在不破坏区块哈希的前提下实现这一点，交易被哈希到一棵**默克尔树（Merkle Tree）**中，只有树的根被包含在区块哈希中。旧的区块随后可以通过修剪树的枝干来压缩。内部的哈希不需要被存储。

> **图4（原文）**：默克尔树示意图。区块头（Block Header）包含 Prev Hash（前一区块哈希）、Nonce（随机数）、Root Hash（默克尔根）。交易 Tx0–Tx3 分别哈希为 Hash0–Hash3；Hash0 与 Hash1 哈希为 Hash01，Hash2 与 Hash3 哈希为 Hash23；Hash01 与 Hash23 再共同哈希生成 Root Hash。即：交易在默克尔树中进行哈希聚合。
>
> **图5（原文）**：修剪后（After Pruning Tx0-2 from the Block）的默克尔树：区块头仅保留 Prev Hash、Nonce、Root Hash，省略了部分交易的分支。

一个不含任何交易的区块头大约为 80 字节。假设每 10 分钟生成一个区块，那么 80 字节 × 6 × 24 × 365 = 每年 4.2 MB。以 2008 年典型电脑配备 2GB 内存来看，加上摩尔定律预测的每年 1.2GB 增长，即使区块头必须保存在内存中，存储也不会成为问题。

## 8. 简化支付验证

在不运行完整网络节点的情况下，也可以验证支付。用户只需要保留**最长工作量证明链的区块头副本**——这可以通过查询网络节点直到确信自己得到了最长链来获取——并获取将交易与其所在区块链接起来的默克尔分支（Merkle Branch）。用户无法自行检查该交易，但通过将其链接到链中的一个位置，可以看到某个网络节点已接受它，而且之后添加的区块进一步确认网络已接受它。

> **图6（原文）**：最长工作量证明链示意图。三个区块头依次排列，每个包含 Prev Hash、Nonce、Merkle Root（默克尔根），通过 Prev Hash 形成链式连接。中间区块头的 Merkle Root 由 Hash01 与 Hash23 推导而来，Hash23 由 Hash2 和 Hash3 生成，Hash3 来源于交易 Tx3，并标注了"Merkle Branch for Tx3"（Tx3 的默克尔分支）。

因此，只要诚实节点控制网络，这种验证就是可靠的；但如果网络被攻击者压制，则更容易受到攻击。虽然网络节点可以自行验证交易，但在攻击者持续压制网络期间，这种简化方法可能被攻击者伪造的交易所欺骗。一种防护策略是：当网络节点检测到无效区块时接受来自节点的警报，提示用户的软件下载完整区块和受警报的交易，以确认不一致性。频繁接收支付的企业，可能仍希望运行自己的节点，以获得更独立的安保和更快速的验证。

## 9. 价值的组合与分割

尽管可以逐个处理币，但为一笔转账的每一分钱都做一笔单独交易是不切实际的。为了允许价值的拆分与组合，交易包含**多个输入和输出**。通常，会有一个来自较大前一笔交易的单一输入，或多个合并较小金额的输入，并且最多有两个输出：一个是支付，另一个（如有）是将找零返还给发送者。

> **图7（原文）**：交易输入输出示意图。一个 Transaction（交易）矩形框，左侧有多个输入（In）箭头，右侧对应多个输出（Out）箭头，以省略号表示存在多个输入输出。

值得注意的是，扇出（fan-out）——即一笔交易依赖于多笔交易、而这些交易又依赖于更多交易——在这里不是问题。永远不需要提取一笔交易历史的完整独立副本。

## 10. 隐私

传统银行模式通过将信息访问限制在相关各方和受信任第三方之间，来实现一定程度的隐私。公开广播所有交易的必要性排除了这种方法，但隐私仍然可以通过在另一处切断信息流来维护：**保持公钥匿名**。公众可以看到有人在向某人发送一笔金额，但没有任何信息能将交易与某个人联系起来。这与证券交易所发布的信息级别类似——单笔交易的时间和规模（"行情"）被公开，但不会说明交易双方是谁。

> **图8（原文）**：隐私模型对比。传统隐私模型（Traditional Privacy Model）：身份（Identities）→ 交易（Transactions）→ 受信任第三方（Trusted Third Party）→ 交易对手方（Counterparty）→ 公开领域（Public）；新隐私模型（New Privacy Model）：身份 → 交易 → 直接进入公开领域（Public），去除了受信任第三方和交易对手方的中转环节。

作为额外的防火墙，每笔交易应使用**新的密钥对**，以防止它们被关联到同一所有者。多输入交易中仍不可避免地存在一些关联——它们必然揭示其输入属于同一所有者。风险在于，如果某个密钥的所有者被揭露，这种关联可能暴露属于同一所有者的其他交易。

## 11. 计算

我们考虑一个攻击者试图生成比诚实链更快的替代链的情形。即使他成功了，这也不会让系统面临任意更改——例如凭空创造价值或拿走从不属于攻击者的钱。节点不会接受无效交易作为支付，诚实节点也永远不会接受包含无效交易的区块。攻击者只能试图更改他自己的某笔交易，以拿回他最近花掉的钱。

诚实链与攻击者链之间的赛跑，可以用**二项随机游走**（Binomial Random Walk）来刻画。成功事件是诚实链延长一个区块，使其领先 +1；失败事件是攻击者的链延长一个区块，使差距 -1。

攻击者从给定差距追上来的概率，类似于**赌徒破产问题**（Gambler's Ruin）。假设一个拥有无限信用的赌徒从一个亏空开始，进行可能无限次的对局以试图回本。我们可以计算他最终回本的概率，即攻击者追上诚实链的概率，如下：

令 $p$ = 诚实节点找到下一个区块的概率
令 $q$ = 攻击者找到下一个区块的概率

$q_z$ = 攻击者从落后 $z$ 个区块处最终追上来的概率

$$
q_z = \begin{cases} 1 & \text{若 } p \le q \\ (q/p)^z & \text{若 } p > q \end{cases}
$$

根据我们 p > q 的假设，随着攻击者需要追上的区块数量增加，该概率呈指数下降。由于概率对他不利，如果他没有在早期侥幸大幅跃进，那么随着他越发落后，他的机会变得微乎其微。

现在我们考虑：一笔新交易的接收者需要等待多久，才能足够确信发送者无法更改该交易。我们假设发送者是一个攻击者，他想让接收者暂时相信自己已付款，然后在一段时间后将交易改回支付给自己。接收者会在发生时收到警报，但发送者希望那时已为时已晚。

接收者在签名前不久生成一个新的密钥对，并将公钥交给发送者。这可以防止发送者通过预先持续工作来准备一条区块链，直到他足够幸运地遥遥领先，再在那一刻执行交易。交易发出后，不诚实的发送者在秘密地开始构建一条平行链，其中包含他的交易的另一个版本。

接收者等待交易被加入一个区块，并且之后链接了 z 个区块。他不知道攻击者的确切进展，但假设诚实区块每块花费平均预期时间，则攻击者的潜在进展服从**泊松分布**，期望值为：

$$
\lambda = z \frac{q}{p}
$$

要得到攻击者现在仍能追上的概率，我们将每个可能进展量的泊松密度乘以他从该点追上来的概率：

$$
\sum_{k=0}^{\infty} \frac{\lambda^k e^{-\lambda}}{k!} \cdot \begin{cases} (q/p)^{(z-k)} & \text{若 } k \le z \\ 1 & \text{若 } k > z \end{cases}
$$

重新整理以避免对分布的无限尾部求和：

$$
1 - \sum_{k=0}^{z} \frac{\lambda^k e^{-\lambda}}{k!} \left(1 - (q/p)^{(z-k)}\right)
$$

转换为 C 代码：

```c
#include <math.h>
double AttackerSuccessProbability(double q, int z)
{
    double p = 1.0 - q;
    double lambda = z * (q / p);
    double sum = 1.0;
    int i, k;
    for (k = 0; k <= z; k++)
    {
        double poisson = exp(-lambda);
        for (i = 1; i <= k; i++)
            poisson *= lambda / i;
        sum -= poisson * (1 - pow(q / p, z - k));
    }
    return sum;
}
```

## 12. 结论

我们提出了一种不依赖信任的电子交易系统。我们从通常的数字签名铸币框架开始，这提供了对所有权的强有力控制，但若没有防止双重支付的方法，它仍是不完整的。为了解决这一问题，我们提出了一个使用工作量证明的点对点网络，用于记录公开的交易历史。只要诚实节点控制多数 CPU 算力，攻击者要在计算上更改这一历史会迅速变得不可行。

该网络以其无结构的简单性而稳健。节点同时工作，几乎无需协调。它们不需要被识别，因为消息不会被路由到任何特定地点，只需尽力而为地投递。节点可以随时离开并重新加入网络，并将工作量证明链作为其离线期间所发生事件的证明。它们用 CPU 算力投票，通过扩展有效区块来表达接受，通过拒绝在其上工作来表达对无效区块的拒绝。任何所需的规则和激励，都可以通过这种共识机制来执行。
