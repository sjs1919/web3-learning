# 一、区块链基础

## 1. 什么是区块链？为什么它被称作"不可篡改的账本"？

区块链是一个**去中心化的、分布式的、按时间顺序追加记录的账本**。数据被封装成"区块"，每个区块通过密码学哈希链接到前一个区块，形成链式结构。

**为什么不可篡改：**
- **哈希链**：每个区块头包含前一区块的哈希，改动任何一个历史区块，后续所有区块哈希全部失配，全网可立刻发现。
- **共识保证**：篡改者要重写后续所有区块并超过 51% 算力/质押，成本极高。
- **分布式冗余**：每个节点都保存完整副本，单点改动无法影响其他节点。

## 2. 区块结构包含哪些部分？

以比特币/以太坊为例，区块包含：
- **区块头（Block Header）**：
  - 父区块哈希（prev hash）
  - 时间戳（timestamp）
  - 默克尔树根（merkle root，汇总所有交易）
  - 难度目标 / nonce（PoW）
  - 区块号（height/number）
  - 状态根、交易根、收据根（以太坊）
- **区块体（Body）**：交易列表（以太坊还有叔块/系统交易）。

## 3. 什么是 Merkle Tree（默克尔树）？作用是什么？

默克尔树是一种**二叉树哈希结构**：叶子是交易哈希，两两配对再哈希，逐层向上最终汇聚为一个根哈希（merkle root）。

**作用：**
- **快速验证**：只需提供一条"默克尔路径"（log n 个兄弟节点哈希），就能验证某笔交易是否属于该区块，无需下载整棵树。
- **轻节点（SPV）**：轻钱包只需保存区块头（含根哈希），即可验证交易。
- **数据完整性**：任意交易改动都会改变根哈希。

## 4. 区块链的"不可能三角"是什么？

- **可扩展性（Scalability）**：高吞吐
- **去中心化（Decentralization）**：节点广泛、无需信任
- **安全性（Security）**：抗攻击、不可篡改

三者难以同时最优。比特币/以太坊 L1 优先去中心化与安全，牺牲扩展性；Layer2、分片、新共识都在尝试突破该三角。

## 5. 分片（Sharding）是什么？

把整个区块链网络划分成多个**分片（shard）**，每个分片独立处理自己的交易和状态，多个分片并行运行，从而提升整体吞吐。跨分片通信需要特殊机制（如信标链协调）。以太坊 2.0（合并后的多阶段计划）曾规划分片，但当前路线图已转向以 Rollup 为中心的扩展方案。

## 6. 什么是 Gas？为什么交易要付 Gas？

Gas 是**执行交易/合约所消耗的计算资源的计量单位**。每个操作码（opcode）有固定 Gas 成本，交易总消耗 = 各操作 Gas 之和。

**作用：**
- **防止资源滥用**：避免无限循环、DoS 攻击。
- **激励矿工/验证者**：Gas 费以 ETH 支付给网络参与者。
- **为计算定价**：`Gas 费用 = Gas 用量 × Gas 价格（gwei）`。
- **Gas Limit**：单笔交易/单个区块能消耗的 Gas 上限。

## 7. 什么是零知识证明？应用在哪？

零知识证明（Zero-Knowledge Proof, ZKP）允许证明者**在不泄露信息本身的前提下，向验证者证明"我知道某个秘密"**。三个性质：**完备性**、**可靠性**、**零知识性**。

**应用：**
- **隐私币**（如 Zcash 用 zk-SNARK 隐藏交易金额与发送方）。
- **ZK-Rollup**：把大量交易的计算结果压缩成一个简洁证明提交到 L1，显著节省 Gas。
- **身份验证 / 合规**：证明拥有资质而不泄露具体数据。

常见算法：zk-SNARK（零知识简洁非交互式论证，需可信设置）、zk-STARK（无需可信设置，证明大、计算重）。

# 二、密码学基础

## 8. 公钥加密与哈希的区别？

- **哈希（Hash）**：单向函数，输入任意长度输出固定长度（如 keccak256 → 32 字节），**不可逆、抗碰撞**。用于地址生成、数据指纹、默克尔树。
- **公钥加密**：非对称，公钥加密 → 私钥解密；或私钥签名 → 公钥验签。用于签名、安全通信。

## 9. 区块链地址是怎么生成的？（以太坊为例）

1. 随机生成 256 位私钥（32 字节）。
2. 用椭圆曲线算法 **secp256k1** 由私钥导出公钥（65 字节：04 + x + y）。
3. 对公钥做 **keccak256** 哈希，取**后 20 字节**。
4. 前面加上 `0x` 得到地址（40 位十六进制）。大写/小写混合是 **EIP-55** 校验和格式，可检测输入错误。

## 10. 什么是数字签名（ECDSA）？

ECDSA（椭圆曲线数字签名算法）用于证明某消息确实由私钥持有者发出且未被篡改：
- **签名**：用私钥对消息哈希签名，生成 (r, s)。
- **验签**：用公钥验证签名。
- **性质**：不可伪造、不可否认、可公开验证。
- 以太坊交易的 `v, r, s` 即为签名值；从签名可**恢复出公钥**，进而反推地址（recovery），这是链上验证消息来源的基础。

## 11. Keccak256 与 SHA-3 有什么区别？

以太坊使用的 **Keccak-256** 是最早的 SHA-3 竞赛候选版本，与最终标准化后的 **NIST SHA3-256** 在**填充方式（padding）**上有细微差别（Keccak 用 0x01 结尾，SHA3 用 0x06），两者结果不同。写合约/验签时需注意区分（OpenZeppelin 的 `keccak256` 是标准 Keccak）。

## 12. 什么是哈希碰撞？抗碰撞性为什么重要？

哈希碰撞指两个不同输入得到相同输出。抗碰撞性要求**难以构造碰撞**。若可轻易碰撞，攻击者可能伪造数据（如让两笔不同交易共享同一默克尔路径），破坏账本完整性。安全哈希（如 keccak256、SHA-256）的碰撞难度约为 2^(n/2)（生日攻击），当前计算能力下不可行。

# 三、共识机制

## 13. 共识机制的作用是什么？

共识机制让**去中心化的节点就同一份账本状态达成一致**，解决"谁有权出块、如何防止双花、如何激励诚实行为"的问题。

## 14. PoW（工作量证明）原理？

节点（矿工）通过暴力尝试 nonce，使区块哈希满足某个**难度目标**（小于目标值）。第一个找到合法 nonce 的矿工广播区块并获奖励。

- **优点**：安全性经过长期验证，简单、无需质押。
- **缺点**：高能耗、吞吐低、出块随机。
- **难度调整**：根据全网算力动态调整目标，保证出块时间稳定。

## 15. PoS（权益证明）原理？

验证者**质押一定数量代币**参与出块和验证。被选中的验证者按质押权重获得出块机会与奖励；若作恶/离线会被**罚没（slashing）**部分质押。

- **优点**：低能耗、无需专用硬件、更高的安全惩罚机制、吞吐可提升。
- **缺点**：富者愈富、冷启动需初始质押。
- 以太坊已于 **2022 年 9 月"合并"（The Merge）** 从 PoW 迁移到 PoS（Beacon Chain + 执行层）。

## 16. DPoS、PBFT、Avalanche 等其它共识？

- **DPoS（委托权益证明）**：Token 持有人投票选举少量代表节点出块（如 EOS、TRON）。效率高但中心化。
- **PBFT（实用拜占庭容错）**：节点间多次通信达成一致，容忍不超过 1/3 的恶意节点。适用于联盟链/许可链（如 Hyperledger Fabric），低延迟但通信开销大，不适合大规模公链。
- **Avalanche（雪崩）**：基于随机抽样投票的亚稳态共识，快速、可扩展。
- **Nakamoto + 其它**：混合机制。

## 17. 什么是"双花"问题？共识如何防止？

双花指同一笔资金被花费两次。防止机制：
- **唯一交易记录**：每笔交易的 UTXO/账户余额一经上链即确定。
- **确认等待**：等待多个区块确认，回滚成本随确认数上升（PoW 需超过 51% 算力重写；PoS 会被罚没）。
- **最终性（finality）**：PoS 的检查点机制在若干 epoch 后提供**确定性最终性**，此后交易不可回滚。

## 18. 交易最终性（Finality）与概率性确认？

- **概率性确认（比特币）**：区块越多，被推翻概率指数下降，但无绝对最终性。
- **确定性最终性（以太坊 PoS）**：验证者对检查点投票，两个相邻检查点被 2/3 验证者确认后，之前交易即**最终确定**（不可回滚）。
- 链下协议（如 Rollup）依赖 L1 的最终性保证。

# 四、以太坊核心

## 19. 以太坊账户模型（Account Model）vs 比特币 UTXO？

- **UTXO（比特币）**：交易引用未花费的输出，每个输出只能花一次；隐私好、并行性高，但编程复杂。
- **账户模型（以太坊）**：全局账户直接持有余额，类似银行账户；**适合复杂智能合约**、状态编程，但需处理重入/顺序问题。

## 20. 以太坊两种账户类型？

- **EOA（外部账户）**：由私钥控制，余额 + nonce，可发起交易、部署合约。
- **合约账户（Contract Account）**：由合约代码控制，**无私钥**，有余额 + storage，只能由 EOA 或其它合约调用来被动执行，且**无法主动发起交易**。

## 21. 一笔交易（Transaction）的完整生命周期？

1. 用户用私钥签名构造交易（from、to、value、data、nonce、gasLimit、gasPrice/maxFee、maxPriorityFee）。
2. 交易广播到节点，进入交易池（mempool）。
3. 验证者/矿工打包进区块，执行交易，消耗 Gas。
4. 状态变更（余额、storage、事件日志）写入状态树。
5. 生成收据（Receipt），包含交易状态（成功/失败）、Gas 使用、日志。
6. 交易确认，纳入最终性。

## 22. EIP-1559 与 Gas 机制改革？

- **EIP-1559（2021，伦敦升级）**：引入**基础费（Base Fee）**随区块利用率动态调整，被**销毁（burn）**；用户另付**优先费（Priority Fee）**给矿工/验证者。
- **maxFeePerGas / maxPriorityFeePerGas**：用户设置上限，多余退还。
- 效果：让 Gas 费更可预测、改善 UX，同时让 ETH 部分通缩。

## 23. EVM（以太坊虚拟机）是什么？

EVM 是**以太坊智能合约的运行时环境**，一个基于栈的图灵完备（受 Gas 限制）虚拟机。合约源码编译为 **EVM 字节码（opcode）** 后执行。所有节点执行相同字节码得到相同结果，保证**状态一致性**。

## 24. 状态树 / 存储结构？

以太坊用 **Merkle Patricia Trie（MPT）** 组织状态：每个账户的状态（余额、nonce、storageRoot、codeHash）和存储（storageRoot）都哈希到状态根。MPT 支持**增删改查且高效验证**，是轻节点校验状态的基础。

## 25. 什么是 EIP？ERC？

- **EIP（Ethereum Improvement Proposal）**：以太坊改进提案，描述技术标准、协议变更等。
- **ERC（Ethereum Request for Comments）**：应用层**标准**，最常用的是代币标准。
- 常见：**ERC-20**（同质化代币）、**ERC-721**（非同质化代币 NFT）、**ERC-1155**（多代币标准）、**EIP-1559**（Gas）、**EIP-1193**（钱包 Provider 标准）、**EIP-712**（结构化签名）、**ERC-4337**（账户抽象）。

# 五、Solidity 与智能合约

## 26. Solidity 核心数据类型？

- **值类型**：`bool`、`uint8-uint256`、`int`、`address`、`bytes1-32`、`enum`。
- **引用类型**：`string`、`bytes`、`array`、`mapping`、`struct`。
- **特殊类型**：`address payable`、`function type`。
- **单位**：`wei`、`gwei`、`ether`（`1 ether = 10^18 wei`）；时间单位 `seconds/minutes/hours/days`。
- **全局变量**：`msg.sender`、`msg.value`、`block.timestamp`、`block.number`、`tx.origin`、`address(this)`。

## 27. storage / memory / calldata 区别？

- **storage**：持久化在链上，最贵，写操作消耗大量 Gas。
- **memory**：函数执行期间内存，临时，较便宜。
- **calldata**：只读的调用参数区（外部调用传入，不可修改），最便宜，用于 `bytes`/`string` 参数。

## 28. 函数可见性与修饰符？

- **可见性**：`public`（内部+外部）、`external`（仅外部）、`internal`（仅本合约及继承）、`private`（仅本合约）。
- **view**：只读状态，不修改。
- **pure**：不读写状态。
- **payable**：可接收 ETH（`msg.value`）。
- **nonReentrant**（OpenZeppelin）：防重入。
- **修饰符（modifier）**：封装前置条件检查与公共逻辑，如 `onlyOwner`。

## 29. 为什么函数需要 payable 才能接收 ETH？

Solidity 中，非 payable 函数收到 ETH 会**回滚（revert）**。显式声明 `payable` 让合约明确接受资金，避免意外锁币。

## 30. 智能合约的执行上下文（msg / tx）？

- `msg.sender`：**直接调用者**（地址）。
- `msg.value`：本次调用携带的 ETH（wei）。
- `msg.data`：调用数据（calldata）。
- `tx.origin`：**交易的最初发起者**（整条调用链的源头）。
- **安全提示**：身份校验用 `msg.sender`，**不要用 `tx.origin`**（存在钓鱼攻击：中间合约代调时 `tx.origin` 仍是受害者）。

## 31. 什么是 reentrancy 重入攻击？如何防护？

重入攻击：在合约对外转账/回调（如 `transfer`、外部调用）后，攻击者在回调中**再次调用原合约函数**，在原函数尚未更新余额前重复提取资金。

**防护：**
- **先更新状态，后转账（checks-effects-interactions 模式）**。
- 使用 **OpenZeppelin `ReentrancyGuard`**（`nonReentrant` 修饰符）。
- 用 `transfer`/`send`（限制 2300 gas）或在转账前标记状态。
- 检查调用深度。

## 32. require / assert / revert 区别？

- **require(cond, msg)**：前置条件校验，失败则**退还剩余 Gas**，可带错误消息。最常用。
- **revert()**：主动回滚并退回剩余 Gas，可携带自定义错误。
- **assert(cond)**：内部不变量检查，失败**消耗全部 Gas**（表示代码有 bug），用于不可能发生的状态。
- 新版 Solidity 推荐**自定义错误（`error`）** + `revert CustomError()`，更省 Gas、可携带参数。

## 33. 如何安全地转账 ETH？

- `address.transfer(value)`：限制 2300 gas（不够接收方做复杂操作，可防部分重入），失败会 revert。
- `address.send(value)`：失败返回 bool，不 revert（需自行处理）。
- `call{value: value}("")`：低层调用，返回 (bool, bytes)，**可携带任意 gas，最灵活**，但必须检查返回值，失败需自行 revert。
- **最佳实践**：用 `call` 并检查返回值，配合 `ReentrancyGuard`。

## 34. 什么是 ERC-20？核心接口？

ERC-20 是同质化代币标准，核心：
- `totalSupply()`、`balanceOf(addr)`、`transfer(to, amount)`、`allowance(owner, spender)`、`approve(spender, amount)`、`transferFrom(from, to, amount)`。
- 事件：`Transfer`、`Approval`。
- 注意事项：**先 approve 再 transferFrom**；注意 `approve` 的竞态（改额度前先归零，或采用"增加到最大值"策略）；**没有返回值检查的接收端**可能吞掉转账（需代币合约实现 `transfer` 返回 bool）。

## 35. 什么是 ERC-721 / ERC-1155？

- **ERC-721**：非同质化代币（NFT），每个 tokenId 唯一，接口含 `ownerOf(tokenId)`、`safeTransferFrom` 等；`safeTransferFrom` 会检查接收方是否实现 `onERC721Received`，防止 NFT 卡死。
- **ERC-1155**：多代币标准，一个合约管理同质化 + 非同质化多种代币，批量转账更省 Gas（如游戏道具）。

## 36. 智能合约如何升级？

链上合约一旦部署不可变，升级方案：
- **代理模式（Proxy）**：存储层与逻辑层分离，代理合约通过 `delegatecall` 委托逻辑合约执行，可替换逻辑地址。需注意 **存储布局冲突**、`initialize` 防重初始化。常用：**Transparent Proxy**、**UUPS**（OpenZeppelin）。
- **升级函数库（diamond）**。
- 升级非万能：状态迁移、权限移交、测试复杂；非紧急优先考虑"新合约 + 迁移"。

## 37. delegatecall 与 call 区别？

- `call`：执行目标合约的代码，**上下文（msg.sender、storage）是目标合约的**。
- `delegatecall`：执行目标合约的代码，但**上下文（msg.sender、msg.value、storage）保持为调用者合约的**。用于代理模式、合约库。
- 风险：delegatecall 到不可信合约 = 让对方操纵你的 storage，极易被攻击。

## 38. 智能合约的构造函数 / constructor 与 initialize？

- `constructor`：部署时执行一次，初始化状态，**部署后不可再调用**。
- 代理模式中逻辑合约的 constructor 不生效（因为它没真正持有存储），需用 **`initialize()` + `initializer` 修饰符**（OpenZeppelin）在首次代理调用时初始化，且仅执行一次。

# 六、DeFi 核心协议

## 39. 什么是 AMM（自动做市商）？恒定乘积公式？

AMM 用**算法定价**替代订单簿，用户与流动性池（Liquidity Pool）直接交易。

**恒定乘积公式（Uniswap V2）**：`x * y = k`
- x、y 为池中两种代币数量，k 恒定。
- 交易 `Δx` 后：`(x+Δx)(y-Δy)=k`，`Δy = y - k/(x+Δx)`。
- 价格 = 池内储备比；**大额交易产生滑点（slippage）**，池越深滑点越小。
- **无常损失（Impermanent Loss）**：价格大幅波动时，LP 收益可能低于单纯持有。

**Uniswap V3**：引入**集中流动性（concentrated liquidity）**，LP 可在指定价格区间提供流动性，资本效率更高，但需要主动管理区间。

## 40. 什么是滑点（Slippage）与滑点保护？

- 滑点：实际成交价与预期价之差，源于池内储备变化。
- **滑点保护**：交易设置 `slippageTolerance` / 最小输出量（`amountOutMin`），若实际输出低于设定值则**交易回滚**，防止被抢跑（sandwich）与剧烈波动伤害。

## 41. 什么是闪电贷（Flash Loan）？

闪电贷允许用户**在同一笔交易内借出大额资金、使用、归还**，无需抵押，只要最终归还本金 + 手续费（否则整笔回滚）。典型场景：套利、清算、杠杆。它是**原子性（同一交易成功或全部失败）**的体现。

## 42. 什么是借贷协议（Compound / Aave）？

- 用户**超额抵押**存入抵押品，按**清算阈值（LT）**借出资产。
- 健康因子（Health Factor）< 1 时可被**清算（Liquidation）**，清算人获得折扣奖励。
- **利率**：由资金利用率（utilization）动态决定，资金池化。
- 收益来源：借出方利息 + 协议激励（如流动性挖矿）。

## 43. 什么是稳定币？分类？

稳定币锚定法币/资产，降低波动：
- **中心化抵押**：USDT、USDC（法币 1:1 储备）。
- **加密超额抵押**：DAI（抵押 ETH 等生成）。
- **算法稳定币**：靠算法/套利维持（如曾经的 UST，崩盘风险高）。

## 44. 什么是跨链桥（Bridge）？风险？

跨链桥让资产在不同链间转移：锁定 L1 资产 → 在目标链铸造等价资产。**风险极高**（大量被黑案例）：锁定资金成为攻击目标；验证机制（轻节点/联邦/乐观）各有信任假设。

## 45. 什么是 DEX、聚合器、机枪池？

- **DEX（去中心化交易所）**：链上撮合（AMM 或订单簿），如 Uniswap、Curve。
- **聚合器（Aggregator）**：对比多 DEX 路由，自动选择最优成交（如 1inch）。
- **机枪池（Yield Aggregator）**：自动策略寻找最高收益（如 Yearn）。

# 七、NFT / DAO / GameFi

## 46. NFT 是什么？与 FT 区别？

- **NFT（非同质化代币）**：每个 token 独一无二，不可互换（ERC-721/1155），代表数字资产所有权（艺术品、域名、游戏道具）。
- **FT（同质化代币）**：可互换，单位价值相同（ERC-20，如 USDT）。
- 元数据常存于链下（IPFS 等），合约存 tokenURI 指向元数据。

## 47. 什么是 DAO？核心要素？

DAO（去中心化自治组织）：由代码（智能合约）和社区治理的组织，**无中心管理层**。
- 治理：Token 持有者投票（提案、执行）。
- 国库：资金由合约管理。
- 工具：Snapshot（链下投票）、Aragon、Compound Governance。
- 挑战：投票参与率、女巫攻击、治理攻击（大户操控）。

## 48. 什么是 GameFi / Play-to-Earn？

GameFi 将游戏与经济激励结合，玩家通过游戏行为获得可交易代币/NFT（如 Axie Infinity）。代币经济（Tokenomics）、双币模型（治理币 + 游戏币）、可持续性是其核心难题（很多项目经济崩溃）。

# 八、扩容与 Layer 2

## 49. 什么是 Layer 2？为什么需要？

Layer2 是在主链（L1）之上的**扩展方案**，把大部分交易处理移到链下，仅把压缩后的结果/证明提交到 L1，兼顾 L1 安全性与更高吞吐、更低费用。

## 50. Optimistic Rollup 原理？

- **乐观**：默认交易有效，**无需立即证明**。
- **挑战期（Challenge Window）**：任何人可在窗口期内提交**欺诈证明（Fraud Proof）**，证明某笔交易有误，若成立则回滚并惩罚作恶者。
- 代表：Arbitrum、Optimism（OP）。优点：EVM 兼容好；缺点：有挑战期，退出有延迟。

## 51. ZK-Rollup 原理？

- 用**零知识证明（ZK）**在链下生成有效性证明（Validity Proof），一次性提交到 L1，L1 只需验证证明。
- 交易被"算术化"成多项式/电路，生成简洁证明。
- 代表：zkSync、StarkNet（STARK）、Scroll。优点：**快速最终性**、无挑战期；缺点：兼容性与证明成本（prover 昂贵）。

## 52. 其它扩容方案？

- **State Channels（状态通道）**：链下双方高频交易，最终只在链上结算两次（如 Lightning）。
- **Plasma**：子链 + 默克尔根提交，退出依赖挑战（已少用）。
- **Validium**：类似 ZK-Rollup 但数据不在 L1 上链（数据可用性在链下），更省 Gas 但信任假设更高。
- **侧链（Sidechain）**：独立共识的旁链（如 Polygon PoS），安全性独立于 L1。
- **应用链 / AppChain**：为特定应用定制的链。

## 53. 数据可用性（Data Availability）是什么？

指"交易/状态数据是否可被任何人获取以验证"。Rollup 需保证数据可用（Optimistic 挑战需要数据；ZK 也需链上数据可验证）。**数据不可用**会导致资金锁死或验证失效。相关技术：Danksharding（blob）、EIP-4844（Proto-Danksharding）。

# 九、智能合约安全

## 54. 常见智能合约漏洞 TOP 10？

1. **重入攻击（Reentrancy）**：DAOs 等被黑主因。
2. **整数溢出/下溢**：旧版本 Solidity（<0.8）需 SafeMath，0.8+ 内置检查。
3. **访问控制缺失**：敏感函数未限制调用者（如未初始化 owner）。
4. **权限过大 / owner 单点**：私钥泄露即全盘皆输。
5. **tx.origin 钓鱼**：用 `tx.origin` 做鉴权。
6. **浮点/精度问题**：除法截断、精度丢失（需用扩大倍数或库）。
7. **外部调用失败未检查**：`call`/`send` 返回值未处理。
8. **存储布局冲突（代理）**：升级导致字段错位。
9. **重初始化 / 抢初始化**：代理合约未用 `initializer` 防护。
10. **随机数不可靠**：用链上变量做随机，可被矿工/验证者预测（需用 VRF）。

## 55. 什么是"检查-效果-交互"（Checks-Effects-Interactions）模式？

安全编码顺序：
1. **检查（Checks）**：前置条件（余额、权限）。
2. **效果（Effects）**：更新自身状态（余额、映射）。
3. **交互（Interactions）**：最后才进行外部调用/转账。
目的：**在对外交互前先更新状态**，从而中和重入攻击。

## 56. 什么是抢跑（Front-Running / Sandwich）？

矿工/验证者或观察交易池的人可在你的交易被确认前插入自己的交易：
- **Front-running**：先于你执行有利可图的交易。
- **Sandwich**：在你买卖前后各插一笔，赚取滑点差。
- **防护**：滑点保护、私密交易（如 Flashbots 私有 mempool）、commit-reveal。

## 57. 智能合约审计怎么做？

- **静态分析**：Slither、Mythril、Semgrep（自动找漏洞模式）。
- **形式化验证**：Certora Prover、Foundry 模糊测试（fuzz）。
- **人工审查**：逐函数审计，重点看外部调用、权限、精度、升级。
- **工具**：Foundry（`forge test`）、Hardhat、Remix 测试。
- 关键产出：**攻击面清单 + 风险分级 + 修复建议**。

## 58. 私钥/助记词安全管理？

- 私钥**永不离开本地**，不存服务器/仓库/前端。
- 用硬件钱包（Ledger/Trezor）、冷存储。
- 助记词（BIP39）纸质备份、多分片（Shamir）、不截图不联网。
- 合约 owner 用多签（MultiSig，如 Gnosis Safe）避免单点。
- 禁止在日志/接口泄露私钥。

# 十、Web3 工程实践与工具链

## 59. 智能合约开发框架？

- **Hardhat**：主流，本地节点、插件丰富、脚本与测试、Gas 报告。网络已演进到 **Hardhat 2/3**。
- **Foundry（forge）**：Rust 编写，**快**，原生 Solidity 测试与**模糊测试（fuzzing）**、`cast` 与链交互、`anvil` 本地节点，已成为社区主流选择之一。
- **Remix**：浏览器 IDE，适合快速原型。
- **Truffle**：老牌，现在较少使用。

## 60. 前端如何与链交互？

- **Provider**：`window.ethereum`（EIP-1193）由钱包注入。
- **库**：**ethers.js**（推荐，现代、TypeScript 友好）、**web3.js**（老牌）、**viem**（轻量、类型安全）。
- **钱包连接**：MetaMask、WalletConnect（QR 扫码）、Rainbow、Account Abstraction（ERC-4337 智能钱包）。
- **读链**：RPC 节点（Infura、Alchemy、自有节点）。
- **链上事件/索引**：**The Graph**（Subgraph 子图索引链上数据）。

## 61. 什么是 The Graph / 子图？

The Graph 是一个**去中心化的链上数据索引协议**：通过定义 Subgraph（映射智能合约事件），把链上事件整理成可查询的 GraphQL API，供前端高效查询（替代直接扫区块）。前端常用 `@apollo/client` 查询子图。

## 62. 什么是 Chainlink？Oracle 的作用？

**预言机（Oracle）**把链外数据（价格、天气、随机数）安全地带入链上。**Chainlink** 是最流行的去中心化预言机网络：
- 价格喂价（Price Feeds）：DeFi 借贷/AMM 的可靠价格来源。
- VRF（可验证随机数）：NFT 抽奖、游戏随机。
- Keepers / Automation：链上任务自动化。
- 为什么需要？**区块链无法主动访问外部网络**，需可信数据源且防操纵（单一喂价易被操纵攻击）。

## 63. 什么是 Account Abstraction（账户抽象, ERC-4337）？

让"账户"不是固定私钥，而是**可由智能合约逻辑控制的账户**：
- 无需私钥也能管理资产（社交恢复、多因子）。
- 批量操作、自定义验证逻辑、代付 Gas（Paymaster）。
- 改善用户体验（无需先有 ETH 支付 Gas）。
- 智能钱包（Smart Contract Wallet）落地。

## 64. 什么是 EIP-712 结构化签名？

EIP-712 定义**结构化、可读**的签名数据格式：把要签名的内容（如订单、授权）组织成 typed data，钱包显示人类可读的结构，减少"盲签"被钓鱼的风险。常用于 DEX 订单（如 Permit2）、登录验证。

## 65. 如何测试智能合约？

- **单测**：`forge test` / `hardhat test`，覆盖正常路径 + 边界 + 攻击路径（重入、权限、精度）。
- **模糊测试（Fuzzing）**：Foundry 随机输入找漏洞。
- **模拟测试**：本地 fork 主网（`anvil --fork-url`）测试真实协议交互。
- **Gas 报告**：优化热路径。
- **测试网**：Sepolia（当前主流）、Holesky；用 faucet 领测试币。

## 66. 如何审计并部署合约？

- 部署前：编译（0.8+ 带 ABI+bytecode）、测试、审计、Gas 优化。
- 部署工具：Foundry `forge create` / Hardhat script / 直接脚本。
- 部署后：验证源码（Etherscan/Sourcify 源码验证）、设置 owner、监控事件。
- 链上广播：上架 Dune 面板、建立索引（The Graph）。

## 67. Web3 常见技术栈（全栈）？

- **后端**：Node.js/TypeScript、Python（web3.py）、Rust（alloy/ethers-rs）、Go（go-ethereum）。
- **智能合约**：Solidity + Foundry/Hardhat。
- **前端**：React/Next.js + viem/ethers.js + wagmi。
- **索引**：The Graph / 自建 Indexer。
- **链**：EVM 系（Ethereum/Arbitrum/OP/Polygon/BSC）为主；Solana（Rust）、Aptos/Sui（Move）。
- **基建**：Alchemy/Infura、IPFS、Chainlink、Safe（多签）。

## 68. 什么是钱包（Wallet）的私钥与助记词层级（BIP）？

- **BIP39**：助记词（12/24 个单词）→ 种子。
- **BIP32/44**：种子 → 分层确定性（HD）私钥路径（如 `m/44'/60'/0'/0/0`，60 为以太坊 coin type）。
- 目的：一个种子派生出多个账户，便于备份与管理。

## 69. 如何判断 Web3 岗位是否靠谱？（结合远程工作手册）

- 看**团队**：资方/运营方/数据/审计合规。
- 看**业务**：数据（合约调用量、资金池规模）是否真实落地（Dune/0xScope/BlockSec）。
- 看**薪资**：发 U/USDT 正常；**只发 token 慎入**；谈薪把补贴写进 offer。
- 看**岗位匹配度**：Web3 面试更重项目履历匹配度 + 编程素养，算法题少。

# 十一、高频面试题速答 50 问

> 精简版速答，用于口头表达。每题一句话核心 + 一句展开。

### 区块链基础
1. **什么是区块链？** 去中心化分布式账本，区块哈希链式连接，不可篡改。
2. **为什么不可篡改？** 哈希链 + 51% 共识成本 + 全网冗余。
3. **区块结构？** 区块头（父哈希、时间戳、merkle root、难度/nonce）+ 交易体。
4. **默克尔树作用？** 汇总交易、轻节点快速验证、防篡改。
5. **不可能三角？** 可扩展性 / 去中心化 / 安全性。
6. **分片是什么？** 网络分区并行处理提升吞吐，跨片需协调。
7. **Gas 是什么？** 计算资源计量，防滥用、激励矿工。
8. **零知识证明？** 不泄露信息证明"知道秘密"，用于隐私与 ZK-Rollup。

### 密码学
9. **地址如何生成？** 私钥 → secp256k1 公钥 → keccak256 → 取后 20 字节。
10. **ECDSA？** 椭圆曲线签名，(r,s) 可恢复公钥/地址，防伪造不可否认。
11. **keccak vs SHA3？** 填充不同，结果不同。
12. **哈希碰撞？** 抗碰撞防伪造数据。

### 共识
13. **共识作用？** 多节点对状态达成一致，防双花，激励诚实。
14. **PoW？** 算力试 nonce 满足难度，安全但耗能。
15. **PoS？** 质押代币出块，作恶被罚没，低耗能（以太坊已合并）。
16. **双花如何防？** 唯一记录 + 确认等待 + 最终性。
17. **最终性？** 概率确认（BTC）vs 确定性最终性（PoS 检查点）。

### 以太坊
18. **账户模型 vs UTXO？** 以太坊全局账户利于复杂合约。
19. **EOA vs 合约账户？** 私钥控制 vs 代码控制，合约不能主动发起交易。
20. **交易生命周期？** 签名 → 广播 → 打包执行 → 收据 → 确认。
21. **EIP-1559？** 基础费销毁 + 优先费，Gas 更可预测。
22. **EVM？** 栈式图灵完备虚拟机，字节码执行，保证状态一致。
23. **MPT 状态树？** 高效增删改查 + 可验证，轻节点基础。
24. **EIP/ERC？** EIP 协议改进，ERC 应用标准（ERC-20/721/1155）。

### Solidity
25. **数据类型？** uint/address/bytes/mapping/struct/string。
26. **storage/memory/calldata？** 持久最贵 / 临时 / 只读最便宜。
27. **可见性？** public/external/internal/private + view/pure/payable。
28. **msg.sender vs tx.origin？** 直接调用者 vs 交易源头，鉴权用前者。
29. **重入攻击？** 回调中重复调用原函数；防：先更新状态、ReentrancyGuard、限 gas。
30. **require/assert/revert？** 前置校验（退 gas）/ 内部不变量（耗光）/ 主动回滚。
31. **安全转账？** call 低层最灵活，必须检查返回值 + 防重入。
32. **ERC-20？** transfer/approve/transferFrom + Allowance；注意 approve 竞态。
33. **ERC-721/1155？** 非同质化 / 多代币批量。
34. **合约升级？** 代理模式 + delegatecall + initialize；注意存储布局。
35. **delegatecall vs call？** 上下文是否保持调用者；风险大。

### DeFi
36. **AMM？** x*y=k 恒定乘积，滑点、无常损失。
37. **滑点保护？** 最小输出量设置，低于则回滚。
38. **闪电贷？** 同一交易借还，原子性。
39. **借贷协议？** 超额抵押 + 健康因子 + 清算。
40. **稳定币？** 中心化抵押 / 超额抵押 / 算法。
41. **跨链桥？** 锁定铸造，风险极高。

### NFT/DAO
42. **NFT vs FT？** 不可互换 vs 可互换。
43. **DAO？** 代码 + 社区治理 + 国库。
44. **GameFi？** 游戏 + 经济激励，可持续性难题。

### Layer2
45. **为什么 L2？** 链下处理 + 压缩提交 L1，兼顾安全与吞吐。
46. **Optimistic vs ZK？** 欺诈证明（有挑战期）vs 有效性证明（快速最终性）。
47. **数据可用性？** 数据能否被获取验证，EIP-4844/Danksharding。

### 安全
48. **常见漏洞？** 重入 / 溢出 / 权限 / tx.origin / 精度 / 存储布局 / 随机数。
49. **CEI 模式？** 检查-效果-交互，先更新状态再交互。
50. **抢跑？** 交易池插入；滑点保护 + 私有 mempool。

### 工具链
51. **开发框架？** Foundry（快+模糊测试）/ Hardhat / Remix。
52. **前端交互？** ethers.js / viem + wagmi + EIP-1193 provider。
53. **The Graph？** 子图索引链上事件，GraphQL 查询。
54. **Oracle？** Chainlink 喂价 / VRF，区块链无法访问外部。
55. **账户抽象？** 合约控制账户，社交恢复、代付 Gas。
56. **EIP-712？** 结构化签名防盲签钓鱼。
57. **测试？** 单测 + 模糊测试 + 本地 fork + 测试网（Sepolia）。
58. **BIP？** 助记词 → 种子 → HD 派生路径。
59. **判断岗位靠谱？** 看团队、数据、薪资形态、内推渠道。
60. **技术栈？** Solidity+Foundry+TypeScript+ethers/viem+The Graph+Chainlink。
